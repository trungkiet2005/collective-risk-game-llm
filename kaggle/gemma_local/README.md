# Local Gemma 4 31B kernel for the rebuttal probes

The Kaggle Benchmarks service returns empty content for `gemma-4-31b-it`, so this kernel runs the
model itself (google/gemma-4/transformers/gemma-4-31b-it, version 1, bf16) on a 4x L4 kernel and
sends it the same prompts as the benchmark task.

- `gemma_local_kernel.py` is generated by `python plan/scripts/make_gemma_local.py` from
  `kaggle/benchmarks/crg_task_server.py` (everything above the SWEEP marker: prompts, parser,
  `decide`, `play_game`, seeds, lottery) and `kaggle/benchmarks/rb_probe_tail.py` (probe items), plus
  `_preamble.py` and `_runner.py` here. Only the model call is replaced.
- Workload: (a) 185-item probe set (`crg-gen-probe`), (b) base self-play at p = 0, 10 games
  (`crg-gen-selfplay-p0`), (c) 65-item target probe (`crg-rb-target`) if time allows.
- Outputs under `/kaggle/working/<task>/gemma-local/`: `games.csv` + `probes.jsonl` (probe sets),
  `games.csv` + `turns.jsonl` (self-play), plus `progress.log` and `status.json`.
- Kernel metadata: `competition_sources ["gemma-4-developer-agent"]`, `model_sources
  ["google/gemma-4/transformers/gemma-4-31b-it/1"]`, internet off, `--accelerator NvidiaL4`.
  Exits with code 42 unless `nvidia-smi -L` lists four L4; a watchdog thread ends the kernel at 3.6 h.

Differences from the benchmark protocol: local transformers inference, not the service; chat template
with thinking switched off; temperature 0.7 with no top-k or top-p; the random stream of each call is
seeded from the same sampling seed, but the text is not reproducible (batched bf16 kernels).
